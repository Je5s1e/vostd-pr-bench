# VOSTD PR Review Bench

基于 [VOSTD](https://github.com/asterinas/vostd) 历史 PR 的代码审查数据集。每个案例包含修改前后的源码、完整 diff 和已确认的问题标签，可用于代码审查工具的评估与改进。

## 数据统计

| 指标 | 数量 |
|---|---:|
| PR 快照 | 50 |
| 已确认问题 | 91 |
| 规范类问题（`guideline`） | 79 |
| 语义类问题（`semantic`） | 12 |
| 原开发集（`dev`） | 20 个 PR / 33 个问题 |
| 原留出集（`heldout`） | 30 个 PR / 58 个问题 |

## 历史审查统计

以下摘自[问题汇总](问题汇总.md)，统计范围为 `asterinas/vostd` 在 **2026-08-15 至 2026-11-12** 期间更新过的 PR。这是历史 review 反馈统计，与上述 bench 的 50 个快照、91 个已确认问题分别计数。

### 统计范围与口径

共检查 **238 个 PR**，收集 877 条行内评论、290 条总体讨论评论及 663 条 review 提交记录。从 532 个行内讨论起点中，排除规范文件自身讨论、自评、解释和重复追问等，归类得到 **492 条行内反馈**；综合行内评论、总体评论和 review 总结，**56 个 PR** 出现了已归类反馈。

同一讨论的回复及总体 review 对行内问题的复述不重复计数；每条行内反馈按主要诉求归入一类，同一 PR 可涉及多个类别。这里统计的是审查提出的问题或修改要求，不等同于 bench 中已确认的问题标签。

### 哪些问题最常出现

以下列出按涉及 PR 数排序的前七类问题。涉及 PR 数综合三种评论来源，行内反馈数仅计入上述 492 条反馈。

| 问题类别 | 涉及 PR | 行内反馈 | 常见要求 |
|---|---:|---:|---|
| 证明、helper 和条件冗余 | 27 | 57 | 删除无用 lemma，内联单次使用 helper，简化重复条件 |
| Verus 表达方式不够简洁 | 25 | 70 | 使用 `returns`、`matches`、链式比较，删除冗余 cast |
| 注释和文档不合适 | 21 | 66 | 精简过长或重复代码的注释，修正 Safety 分类 |
| 未保持原始源码 | 20 | 51 | 避免不必要的 exec 改写、原注释修改和代码丢失 |
| 模型与资源设计过重或不合适 | 20 | 48 | 减少重复模型，简化权限流向与 `Inv` 设计 |
| 没有复用已有模型和 API | 19 | 55 | 复用 vstd 定义及 `dual_spec`，减少手写量词和递归 |
| 契约不完整、过强或对调用者无用 | 17 | 38 | 补全结果关系、panic 和 frame condition，检查前置条件可用性 |

六个 PR 集中了 55.9% 的行内反馈，因此这里按涉及 PR 数排序，减少单个大型 PR 对排名的影响。

## 数据结构

```text
vostd-pr-bench/
└── pr-<编号>-<head短SHA>/
    ├── metadata.json   # PR 标题、链接、base/head 提交及变更路径
    ├── diff.patch      # base → head 的完整 diff
    ├── labels.json     # 问题类别、描述、代码位置及判断依据
    ├── before/         # 修改前的源码
    └── after/          # 待审查版本的源码
```

两侧源码包含完整 `ostd/` 及本次修改涉及的目录外文件，路径与上游仓库一致。`after/` 对应选定的历史审查版本。

## 使用方法

1. 选择一个案例，例如 [PR #812](vostd-pr-bench/pr-812-4121eb1c32b0/)。
2. 阅读 `metadata.json` 和 `diff.patch`，结合 `before/`、`after/` 中的源码审查修改。
3. 将审查结果与 `labels.json` 中的已知问题对照；标签包含问题描述、位置和判断依据。

数据可直接在本地阅读，无需安装工具或访问 GitHub。用于模型评测时，提供源码和 diff，将 `labels.json` 及元数据中的 `known_issue_count` 留作评分信息，不作为模型输入。

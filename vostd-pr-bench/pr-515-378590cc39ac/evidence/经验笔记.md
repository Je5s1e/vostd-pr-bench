# PR #515：线性资源的构造必须发生在正确的 tracked 模式中

第 471 / 847 项 · 所有权与生命周期 · 归档状态 `MERGED` · 2026-06-12

原题：fix missing tracked variable

## 最核心的经验

RcuPtrGhost 不再先在一个无法正确衔接的 proof_decl 中构造，而是直接在 AtomicPtr::new 的 Tracked 参数里建立。编译阶段找不到变量或模式不匹配时，应修复证据的作用域与模式边界，不能用任意占位资源代替；const 函数的处理也要与验证入口分开检查。

## 精简例子

```diff
         Self {
             ptr: AtomicPtr::new(
                 Ghost((Ghost(true), PhantomData::<*const <P as NonNullPtr>::Target>)),
                 core::ptr::null_mut(),
-                Tracked(ptr_ghost),
+                Tracked(
+                    RcuPtrGhost {
+                        current: None,
+                        retired: Map::tracked_empty(),
+                        returned: Map::tracked_empty(),
+                    },
+                ),
```

来源：`ostd/src/sync/rcu/mod.rs`；原始 diff 第 167–178 行。 [查看完整 diff](../../02_形式化验证PR_含diff/PR-00515/changes.diff)。原始摘录保留 `+` / `-` 表示新增 / 删除，依赖原有上下文，不是独立可编译程序。

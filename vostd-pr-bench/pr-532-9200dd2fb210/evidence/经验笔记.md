# PR #532：泛型签名并不能掩盖不变量中写死的架构常量

第 488 / 847 项 · 规约与模型 · 归档状态 `CLOSED` · 2026-06-16

原题：fix: Decouple arch-specific constants from `PagingConstsTrait` trait definitions, fix specifications, and prove axioms.

## 最核心的经验

该提案发现 CursorOwner::inv 直接使用层级 4、3，以及固定 4096 和 512，因而无法支撑其他页表配置。泛化应贯穿类型、执行函数、模型与引理，而不只是给函数加 C 参数；不能让自动证明把 x86 数值重新塞进 trait 前提，制造表面上的通用性。

## 精简例子

```diff
 /// `NR_ENTRIES * page_size(level - 1) == page_size(level)` for level in [2, NR_LEVELS + 1].
 /// A huge page at `level` consists of NR_ENTRIES sub-pages each of size `page_size(level - 1)`.
-pub proof fn lemma_nr_entries_times_sub_page_size(level: PagingLevel)
+pub proof fn lemma_nr_entries_times_sub_page_size<C: PagingConstsTrait>(level: PagingLevel)
     requires
-        2 <= level <= NR_LEVELS + 1,
+        2 <= level <= C::NR_LEVELS() + 1,
     ensures
-        crate::specs::arch::NR_ENTRIES as int * page_size((level - 1) as PagingLevel) as int
-            == page_size(level) as int,
+        nr_subpage_per_huge::<C>() as int * page_size::<C>((level - 1) as PagingLevel) as int
+            == page_size::<C>(level) as int,
```

## 普通评论 · rikosellic · 2025-08-06T09:01:27Z

[原文](https://github.com/asterinas/vostd/pull/175#issuecomment-3158423715)

@Xungan2  It seems there is a fundamental error in `protocol_lock_start`. At the end of the traverse phase, we do lock the subtree root if it is not stray, so `protocol_lock_start` will create a locked cursor `Locking(nid,nid+1)` instead of locking nothing `Locking(nid, nid)`. I think a correct `protocol_lock_start` should be something like 
```
transition! {
    protocol_lock_start(cpu: CpuId, nid: NodeId) {
        require(valid_cpu(pre.cpu_num, cpu));
        require(NodeHelper::valid_nid(nid));

        remove nodes -= [ nid => NodeState::LockedOutside ];
        remove cursors -= [ cpu => CursorState::Void ];
        add nodes += [nid => NodeState::Locked];
        add cursors += [ cpu => CursorState::Locking(nid, nid+1) ];
    }
}
```
Note that it changes a `LockedOutside` node in the traverse phase into a `Locked` node in the locking phase. Perhaps we should add another requirement regarding the `strays` condition in the transition, and also modify the well-formedness of `CursorState::Locking` to ensure that the root is both present and locked.

Enable and verify `has_avx()` and `has_avx512()` in the existing x86 module, adding 16 Verified executable LoC. Per-call ghost samples specify the original leaf-0 gate and the exact AVX/AVX-512F bit checks; other inactive code and existing comments are preserved.

Replace the core CPUID intrinsics with the already specified `native_cpuid::cpuid_count`. The pinned x86/raw-cpuid implementation delegates to the same intrinsic and preserves all four registers, so query arguments and order are unchanged. No trusted boundary is added. The contracts describe this invocation's samples; they do not assume consistency across reads or prove all hardware and OS conditions for executing AVX instructions.

Thanks for taking a look. The purpose of CpuidFeatureSamples is to let the postconditions refer to the register values read during this invocation. The existing CPUID specification leaves each call’s results unconstrained, so we cannot assume that another read would return the same values.

max_leaf records the first read’s EAX for the leaf gate, while feature_bits records the queried ECX/EBX value, or None if the function returns early. Together, they let us specify the exact Boolean result and its relationship to the leaf gate.

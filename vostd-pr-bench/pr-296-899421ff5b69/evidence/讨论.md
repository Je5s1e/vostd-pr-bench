## 普通评论 · rikosellic · 2026-02-09T07:24:56Z

[原文](https://github.com/asterinas/vostd/pull/296#issuecomment-3869820419)

The question is the design of `Node::new` and `TreeNodeValue::rel_children` makes `Node::default(lv).rel_children(None)` a compulsory requirement to prove `new_preserves_inv`. I've thought about decomposing the properties into several traits, but this is not an easy one, because `TreeNodeValue::default()` requires a `nat` argument. So modifications of these are good.

But I don't like the modification in `recursive_insert` and `recursive_remove`. They should just insert or remove, and I don't think we should check `rel_children` in this function. Instead, we may need another function to check whether the `inserted/removed` node satisfies `rel_children` and add it to the preconditions of `insert/remove_preserves_inv`. I've removed the change in these two functions.

This precondition narrows `cursor_mut_at` so it no longer covers the documented list-owned-frame case. `LinkedListOwner` tracks link slot permissions in its `perms` map, while `MetaRegionOwners::slots` is for slots not otherwise owned, so a frame already in the list can legitimately be absent from `regions.slots`; requiring it here makes callers unable to get a cursor for such frames. Use the matching permission from `owner.perms` (or express that as the contract) instead of requiring the global slot map to contain the frame.

## 普通评论 · SNoAnd · 2026-05-22T08:19:19Z

[原文](https://github.com/asterinas/vostd/pull/454#issuecomment-4516892458)

This is tricky. Because the frames owned by the `LinkedList` always come from `UniqueFrame`, we transfer ownership to the list itself, and the perms are carried by `owner.list_own.perms` and not found in `regions`. But the proof code in this function is old, and doesn't really work with the approach; it assumes that the perm can be found in `regions`.

The idiomatic approach would be to find `paddr` in `owner.list_own.perms` and extract it. `in_list` should match iff the perm is actually present.

## 普通评论 · SNoAnd · 2026-05-25T23:12:14Z

[原文](https://github.com/asterinas/vostd/pull/454#issuecomment-4537882561)

This is good progress. It is illustrating an issue with the permission division, though. It works great when the chosen `paddr` is part of the linked list, because we can access the permission directly. But if not, we still need to access the permission in order to read the slot _before_ checking the list id. Hence the preconditions here asserting that the permission must otherwise be in `regions`.

I think that removing those preconditions will actually require us to retire the "uniquely-owned perms live with their owners" pattern and just keep all slot permissions in `regions` at all times. I have some sketches of what that looks like, I can see how tractable it would be to make the migration.

Currently this proof is vacuous if `paddr` is in a different linked list, or if it corresponds to a `UniqueFrame` or a page table node, the other instances where the permission is allowed to leave `perms`.

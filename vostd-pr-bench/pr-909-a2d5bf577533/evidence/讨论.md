This carries ownership permissions across `Arc` raw-pointer conversions. `'a` bounds a borrowed permission, while `T` remains `'static`.

`None` represents a freshly wrapped owner; `Some` contains either an owned permission or its borrow. The permission also preserves allocation identity.

`ManuallyDrop` prevents borrowed handles from decrementing the strong count, and `into_arc` requires ownership. Owning handles must be consumed explicitly; otherwise they leak. I've clarified this in the documentation.

The blocker is allocation identity. The current Verus model can equate two `Arc<T>` values with equal pointee values, even when they belong to different allocations. After restoring a plain Arc from a raw pointer, the specs preserve its value but cannot establish that converting it back returns the original pointer. This blocks the pointer-equality assertion in `Either::left_pointer`.

`ArcWithPtr` carries that identity as ghost state, together with the raw-pointer permission. It also distinguishes owned permissions from borrowed ones: only an owning handle can become an ordinary, independently droppable Arc. Borrowed handles use `ManuallyDrop` to avoid decrementing the strong count.

Adding an uninterpreted `ptr()` to plain Arc does not resolve this: equal Arc values would necessarily have equal `ptr()` results, incorrectly identifying distinct allocations.

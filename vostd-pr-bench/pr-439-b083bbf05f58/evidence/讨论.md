Yeah, this is just a WIP that I was playing with while waiting on a blocker from the `io` work, so take it with a grain of salt. I wanted to see how easy it would be to approximate a deep embedding in verus. A rigorous statement of soundness needs to do induction over arbitrary call sequences. Currently we make that argument on paper rather than in Verus, because Verus obviously can't quantify over functions. This file is an experiment in working around that limitation by defining each function identifier in a big enum and treating calls as transitions in a proof-mode state machine.

Consider only splitting/advancing `writer_owner` after validating `remain()` and after a successful read, or add a way to recombine/undo the split on error.

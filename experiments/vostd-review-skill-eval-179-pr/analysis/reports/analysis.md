# VOSTD 全量 review 效果分析与改进建议

本次补齐剩余 **83 份 review、127 个标签**，当前统计覆盖 **179/179 个快照、164 个不同 PR、244 个标签**。按沿用的根因匹配口径，完整命中 **58/244 = 23.8%**，完整加部分命中 **65/244 = 26.6%**。核心问题是：报告能发现部分显式信任缺口及 API 契约问题，但大量具体维护规范和资源关系问题未被覆盖。报告提出的其他问题仍需单独裁决，不能据未匹配比例声称误报率。

这是一轮 **fast 静态配置的描述性评估**，不是完整 skill 的受控效果实验，也不是已验证隔离的封存测试。没有重跑 PR review、历史 Verus、编译或测试，没有修改原始 review、benchmark 或 skill。

## 1. 完成范围与可复现性

- 本轮冻结时刻：`2026-11-21T09:04:41.975490+00:00`，统一使用 UTC；不是各 PR 的审查时点。
- 179 份报告均非空，并包含 High/Medium/Low、结论及 Evidence check record，均提及 fast。此处“完成”指文件产物完整，不代表检查任务全部执行或代码通过验证。
- 原截点 96 份及其统计、报告、脚本完整保存在 [baseline-96](../archive/baseline-96/分析报告.md)。本轮保留其 117 条匹配判断，补入 83 份的 127 条逐标签判断。
- #337、#419、#615 的报告哈希较基线变化；逐行检查仅标题或 Bottom line 格式更新，finding 内容未变。
- 179 份 diff 与 benchmark 及 metadata 中的哈希一致；标签涉及的 **231 个不同“样本/版本/文件”**逐字节一致。所有冻结 review 哈希复验通过，基线标签未变化。
- skill 归档中的源文件与当前 review 工作区副本一致。这只证明当前文件一致，不能追溯证明每次运行实际加载的版本。
- 修复提取器：#868 Low 表格里的 `None` 不再算 finding。全量实际抽取 300 条，而非包含占位符的 301 条。

## 2. 判定口径及边界

F 表示报告明确指出标签根因；P 表示仅覆盖具体子义务；M 表示未匹配该根因；X 表示标签中的 before 问题在 after 已修复。仅同文件、同规则、同属信任或所有权问题不构成命中。P 不计入严格召回，宽松召回也不将 P 任意赋成半分。

新增判断由单一 agent 对照冻结报告、标签描述及理由逐条完成，并针对关键范围/部分命中案例回查源码。未进行独立人工校准。原报告的“人工匹配”措辞不能作为本轮独立人工验证的证明；旧判断沿用，未宣称重新认证全部源码真值。每条新增理由见 [additional_judgments.txt](../evidence/additional_judgments.txt)，全量见 [逐条匹配.md](label-matches.md)。

原始报告的一条 finding 可包含几个明确子声明。例如 #797 F1 分别点出 partition、coalesced、preserves_types 三个不透明保证，可对应三个标签；没有指出的 aligned_regions 不给分。反之，#35 的同一标签需要两个 finding 合并说明。因此这里的 **300 是原始报告项数**，不是已原子化、去重后的 N，不能直接套用项目协议中的 precision、未决率或重复率公式。

PR 等权指标仅减弱多快照 PR 的权重；没有跨快照根因去重，没有合并依赖 PR，也没有将 244 个标签当作独立样本做显著性推断。

## 4. 剩余83份带来的主要发现

### 4.1 有效检出应保留为回归正例

- **构建符号闭合：** #78 F1 精确找到枚举改名后 6 处旧变体；#93 F1 找到已删除 axiom 的残留 broadcast use。说明便宜的跨引用检查能产生直接命中。
- **调用者可用的契约：** #789 F1 识别 closed 前提无引入规则；#797 F1 识别三项公开后置性质缺可用解释；#82 F1 识别 ilog2 的非零域。
- **关系与泛型：** #897 F1 指出 ref_rel_perm 将 reference inv 仅作为 antecedent，无法向前导出有效性；#855 F1 指出 CPU 四级常量排除了三级 IOMMU。
- **具体维护规则：** #856 合并 imports、#819 两个 volatile 规格使用 addr accessor、#906 原位保留 parser 均准确对齐。#738 的保存/表示依据问题和 #782 第一快照的重复不变量也有明确子声明匹配；匹配不为评论附带的所有语义断言背书。

### 4.2 很多漏检是“看了同一处，却处理了另一问题”

- #659 指出同一 helper 命名前缀，但漏掉空体、单调用、冗余边界。
- #679 指出 helper 的 nn 参数不必要，但漏掉 lemma_ 前缀。
- #703 引用了重复 ghost 字段和自定义 range model，却只讨论 free 的语义契约。
- #812 讨论 Result 成功/失败方向，却未覆盖标签中的 `is Ok` 写法。
- #900 提出 IRQ guard 非 LIFO 析构风险，却没有指出“禁抢占被替换为禁中断”的特定执行变更。
- #927 检出 Pod/derive 的其他候选，却漏掉该 PR 的 VM 成功分支契约与 Vec 索引 admissibility；#924 曾报告相近 VM 契约缺口，说明相邻案例不能保证稳定迁移。

这些例子支持增加可审计的覆盖步骤，而非只向 skill 再追加“注意所有权/契约”。没有完整轨迹，仍不能确认究竟是未检查、推理失败，还是输出时被筛掉。

| 样本 | 已覆盖 | 未覆盖或政策差异 |

### 4.4 保存执行代码的规则执行不稳定

报告能发现大段执行代码被注释、API 被删除等明显变化，却多次漏掉原注释保存、字段可见性、verus_spec 附加方式、原 intrinsic 与 wrapper 的取舍。#763/#920 第一快照甚至将标签要求修正的改动判为可接受。这提示需要按已固定的历史规范逐项检查，区分实际行为变化、来源记录、纯排版和任务政策；不能把所有差异都自动升级为阻塞问题。

## 5. 范围、隔离和结论限制

**三个已修复标签。** #403 为 take/put 改 borrow；#499 为删除替代模型并恢复实际实现；新增 #862 将 partition 的整体性质移出量词，after 已修复空真。#862 报告正确解释了修复，无需输出 after 缺陷。#763 虽定位 before，但标签说的是删除原始源码记录，本身仍适用，不能仅依据 before 字段自动剔除。

**diff 与快照任务仍混合。** #70/#74 等标签的证明缺口可能与本次 changed hunk 不同；#71/#868 报告以未扩大契约/信任为主要理由，而标签关心整个调用链或既有 owner 流。需要逐标签确定 introduced、materially_affected、pre_existing、fixed_in_after、unknown，M 当前只表示未匹配，不一律意味着在既定任务范围内本应检出。

**输入隔离尚未成立。** 当前 pr-test 没有 labels.json，但 **16 个样本仍有 evidence 目录**；例如 #143 的 review-summary.json 有“以父条目的精确身份约束新节点锁定”的 core_lesson。详见 [input_exposure_audit.json](../provenance/input_exposure_audit.json)。这证明可见材料中仍有答案提示风险；缺少原始轨迹，不能断言 Reviewer 实际读过。评估器读取标签是本次评分所需，和 Reviewer 的无标签隔离是不同角色要求。

AGENTS.md 已列 #628/#632/#770/#856/#886/#931 为已暴露案例。只删除这六个 PR 的探索性敏感性统计为 **57/237 = 24.1%**，并不消除 skill 历史例子、其他 evidence 或依赖重叠。当前快照已被逐标签分析，后续从这些结果改 skill 后重测，只能作为开发回归；新的泛化结论需要另行冻结、尚未暴露的数据。

**未测指标明确留空。** 没有完成300条原始意见的原子化、真伪裁决和重复合并，因此不报告真实 precision、F1、确认误报/PR、原子未决率或重复率。没有预定输出K及原子格式，不补造 Recall@K。没有原始轨迹，不以文件mtime估计时延，也不补造 token、工具调用或策略执行率。历史 oracle 未执行，不能把标签中的历史修复说明当成本次工具复现。

## 6. 改进优先级

1. **先修评测与运行协议。** 白名单导出 reviewer 输入，排除 evidence、历史报告及标签；由 runner 写 sample/SHA/diff/skill 哈希、模式、预算与工具轨迹。冻结 diff-review 和 snapshot-audit 的边界以及历史规范版本，单列修复识别。
2. **fast 也保留规则覆盖表。** 对变更定义及直接依赖记录“触发/通过/不适用/未检查 + 位置”。先覆盖未使用helper、复用、命名、mode、imports、量词及精确结果形式。搜索只是候选生成，不能据无文本引用直接删除宏、trait或broadcast入口。
3. **将 API/资源检查变成闭合检查。** 每个公有API列输入域、Ok/Err/None、最终可变状态、返回关系、权限归还、跨对象身份与跨模块可用性；对 pop、转换、失败重试做“两次调用/一次失败/一次drop”的最小推演。对量词分别试空集、域外witness及矛盾前提。
4. **结构正确性优先排查。** 新增/删除/改名符号检查声明、调用、宏块及参数；工具升级核对锁文件，CI 检查干净runner依赖。历史工具不可用时报告 unavailable，不能暗示通过。
5. **控制发布意见的证据强度。** 每条保留diff hunk、根因、前提、具体后果、反证检查与证据等级。对“新增性”、第三方PCell/unsafe边界、当前未启用模块及硬件假设做反驳；优先裁决高严重度未匹配意见。上游化建议要求先查本地复用，不让泛化建议占掉具体问题预算。
6. **再做局部策略对比。** 使用本批作为已暴露开发池，比较当前fast、fast加结构清单、fast加资源/契约步骤；固定在线预算，保存失败候选，以同PR成对结果检查检出、裁决后的误报与成本。完整persona配置可另设比较，不与策略变化混为一因。用新的未暴露PR检验迁移。

这些是待验证的改进假设，本轮没有修改 skill。具体候选、正反例及验收方向另见 [总结与改进建议.md](summary.md)。
